## 1. PBR workflow fundamentals in Blender (Principled BSDF, color spaces, normal vs bump vs displacement, adaptive subdivision)

### Takeaway
Only Base Color (and emission/color-type maps) is sRGB. Roughness, Metallic, Normal, Height, AO and Alpha are data and must be set to Non-Color. Normal maps go through a Normal Map node, and fine detail is best done with Bump (cheap) or true displacement (Cycles, needs dense or adaptive geometry). The Principled BSDF was overhauled in 4.0, gained Thin Film in 4.2 and metallic Thin Film in 5.0, and gained Thin Wall mode in 5.2 LTS.

### Cited Findings
**Color space and map wiring**
- Roughness, Normal and other non-color maps must be set to Non-Color Data. Normal map chain: Image Texture (Non-Color) → Normal Map node → Principled BSDF Normal. — [cgbookcase](https://www.cgbookcase.com/learn/how-to-use-pbr-textures-in-blender), [uhiyama-lab PBR workflow](https://uhiyama-lab.com/en/notes/blender/materials-shading-pbr-workflow/)
- "Only Base Color is color; everything else is data." Leaving Roughness/Metallic on sRGB is described as the single most common error (roughness looks too glossy/flat, metal goes wrong). The search summary did not tie this to one page, so the attribution is a candidate set. — [StraySpark PBR setup](https://www.strayspark.studio/learn/tutorials/set-up-strayspark-pbr-materials-blender), [uhiyama-lab](https://uhiyama-lab.com/en/notes/blender/materials-shading-pbr-workflow/)
- A typical PBR set is base color, roughness, normal, AO and sometimes displacement/metalness. At minimum, color + roughness + normal are needed for a surface to react correctly to light. AO "enhances crevices"; Height "adds real geometry detail if enabled". — [CG Cookie PBR thread](https://cgcookie.com/community/22440-pbr-physically-based-rendering-texturing), [Elephorm Blender 5 course page](https://www.elephorm.com/formation/apprendre-blender-5-les-fondamentaux/generer-une-texture-realiste-pour-blender-avec-lintelligence-artificielle)

**Normal-map convention (OpenGL vs DirectX)**
- OpenGL: green channel Y points up. DirectX: green channel points down. Applying a DirectX map without conversion inverts bumps and dents. Blender uses OpenGL; Unreal uses DirectX. — [CGAxis OpenGL vs DirectX](https://cgaxis.com/which-normal-map-should-i-use-opengl-or-directx/), [Blender API Normal Map node (5.1)](https://docs.blender.org/api/5.1/bpy.types.ShaderNodeNormalMap.html)
- Substance 3D Painter ships a "Blender (Principled BSDF)" export template. It exports Basecolor, Normal (converted to OpenGL), Metallic, Roughness, Emission, Alpha and Displacement. — [Blender Artists: Substance Painter and Blender](https://blenderartists.org/t/substance-painter-and-blender/1507370), [DigiKrafting add-on](https://github.com/DigiKrafting/blender_addon_substance_painter)

**Albedo / metal / dielectric value ranges**
- For non-metals, base color is commonly kept between about 50-60 and 240 sRGB. Some sources use 30 as the black floor and 240 sRGB as the upper limit (snow). Metals sit around 0.5-0.98 linear (about 180-250 sRGB). Common dielectrics have F0 around 2-5%. These come from game-PBR guides (Polycount threads, Shinsoj albedo chart, GDC 2016 PBR slides) and are not Blender-specific. — [Shinsoj chart](https://shinsoj.artstation.com/blog/Q9j6/pbr-color-space-conversion-and-albedo-chart), [Polycount](https://polycount.com/discussion/comment/2713327/), [GDC 2016 slides](https://www.slideshare.net/slideshow/gdc-2016-endtoend-approach-to-physically-based-rendering/60294641)

**Bump vs normal vs displacement**
- Bump node inputs: Height, Distance (a multiplier on height; 1 unit = 1 m), Strength. For subtle detail that matches real 1-2 mm displacement, a Distance of 0.001 with Strength around 2 is suggested. Some artists use 0.1/1000 for 0.1 mm detail. The forum advice is to check that bump produces similar normal changes to real micro-displacement. — [Blender Artists: Bump Distance](https://blenderartists.org/t/should-bump-node-distance-ever-really-be-higher-than-0-001/1418023), [Blender manual Bump node (4.5)](https://docs.blender.org/manual/nl/4.5/render/shader_nodes/vector/bump.html)
- Image Texture interpolation: Linear is regular quality, Cubic is smoother, and bump maps should use Cubic for best results. Closest is for pixel art. — [Blender manual Image Texture node (4.3)](https://docs.blender.org/manual/sr/4.3/render/shader_nodes/textures/image.html), [Blender manual (older)](https://www.blender.org/manual/en/render/shader_nodes/textures/image.html)
- Displacement node: Midlevel default 0.5 (lower values push surfaces in, higher push out), plus a Scale input. By default Blender renders displacement as bump only. True displacement needs the material's Displacement method set accordingly, and the mesh must be finely subdivided. The pages returned are older manual versions (2.80/3.1). — [Blender manual Displacement node](https://www.blender.org/manual/en/render/shader_nodes/vector/displacement.html), [2.80](https://docs.blender.org/manual/en/2.80/render/shader_nodes/vector/displacement.html)

**Cycles adaptive subdivision (micro-displacement)**
- Requires the Experimental Feature Set (in the Blender 4.1/4.2 manuals). The Subdivision Surface modifier then subdivides at render time using OpenSubdiv, giving more subdivision to near objects and less to far ones. Render settings: scene Dicing Rate (micropolygon size in pixels; 1 px means roughly 1-pixel polygons), per-object Dicing Scale (multiplier on the scene rate), and Offscreen Scale (a lower value gives better off-screen reflections/shadows, a higher value uses less memory). — [Manual: Adaptive Subdivision (4.1)](https://docs.blender.org/manual/en/4.1/render/cycles/object_settings/adaptive_subdiv.html), [Manual: Cycles Subdivision settings (4.1)](https://docs.blender.org/manual/de/4.1/render/cycles/render_settings/subdivision.html), [Manual (4.2)](https://docs.blender.org/manual/sr/4.2/render/cycles/object_settings/adaptive_subdiv.html)
- Limitations: multi-user object data become single-user (more memory, so non-adaptive subdivision is better for those). Instances are not tessellated individually; the original is tessellated and duplicated, so place the original at the instance closest to the camera. — [Manual: Adaptive Subdivision (4.1)](https://docs.blender.org/manual/en/4.1/render/cycles/object_settings/adaptive_subdiv.html)

**EEVEE displacement**
- Since 4.2 (EEVEE Next), shader displacement works in EEVEE via "Displacement and Bump" in the material settings. Reported issues: edge splitting with flat shading, odd transparency splotches with noise + displacement, and distorted reflection edges. Complex shaders compile slowly in EEVEE. — [Blender 4.2 EEVEE release notes](https://developer.blender.org/docs/release_notes/4.2/eevee), [iRendering](https://irendering.net/blender-4-2-explore-whats-new-in-eevee-next/), [DevTalk EEVEE-Next feedback](https://devtalk.blender.org/t/blender-4-2-eevee-next-feedback/31813?page=15)

**Principled BSDF layers (version-specific)**
- [4.0] Specular and transmission are now primarily driven by IOR. A new IOR Level input scales specular strength and is the one to texture. Metals get an F82 tint (edge tint) for artist-friendly complex-IOR looks. Coat sits above emission and gained Tint and IOR inputs. Sheen uses a new microfiber model, is the top layer, and suits cloth or dust on any material. Subsurface now uses the base color, with a new Subsurface Scale input. — [Blender 4.0 Shading release notes](https://wiki.blender.org/release_notes/4.0/shading/), [CG Channel: 5 key features in 4.0](https://www.cgchannel.com/2023/11/5-key-features-in-blender-4-0/), [It's FOSS](https://itsfoss.com/blender-4-0-release/)
- [4.0 manual] Sheen "simulates very small fibers" and adds a soft velvet-like reflection near edges. Sheen Weight and Sheen Roughness both run 0-1, with a Tint color. — [Principled BSDF manual (4.0)](https://docs.blender.org/manual/zh-hans/4.0/render/shader_nodes/shader/principled.html)
- [4.2] Thin Film (iridescence): thickness in nm (0 disables it; a soap bubble is about 200-500 nm). IOR default is 1.33 (water), and 1.33-1.5 is suggested for soap bubbles. The film sits on top of the metal, transmission and specular components. — [Principled BSDF manual (4.3)](https://docs.blender.org/manual/zh-hant/4.3/render/shader_nodes/shader/principled.html), [Manual (latest)](https://docs.blender.org/manual/sl/latest/render/shader_nodes/shader/principled.html), [Blender Artists 4.2 alpha test](https://blenderartists.org/t/trying-out-the-4-2-0-alpha-thin-film-iridescence/1528296/3)
- [5.0, Nov 2025] Thin film now supported on metals (Principled + Metallic BSDF). More accurate random-walk subsurface scattering with multiple bounces (less darkening, some render-time cost). Blue noise sampling for Cycles. New null-scattering volume algorithm. — [Blender 5.0 Cycles release notes](https://developer.blender.org/docs/release_notes/5.0/cycles/), [Thin Film and Blue Noise release-notes PR](https://projects.blender.org/blender/blender-developer-docs/pulls/64/files)
- [5.0] Color management overhaul: ACES 1.3 and 2.0 workflows, built-in ACES 2.0 view transform (SDR and HDR), HDR display support (Rec.2100-PQ/HLG, AgX HDR), per-file custom working space. — [It's FOSS](https://itsfoss.com/news/blender-5-0-release/), [Digital Production](https://digitalproduction.com/2025/09/02/blender-5-0-ships-built-in-aces-2-0-view-transform/), [OSArch release post](https://osarch.org/2025/11/18/blender-5-0-released/)
- [5.1, Mar 2026] New Raycast shader node (EEVEE, screen-space only), faster shader compilation (GPU shaders compile 25-50% faster in Barbershop), EEVEE texture memory reduction, planar reflections with glossy/refraction, Cycles GPU roughly 5-10% faster. — [CG Channel: Blender 5.1](https://www.cgchannel.com/2026/03/discover-5-key-features-in-blender-5-1), [Linuxiac](https://linuxiac.com/blender-5-1-3d-creation-software-released/)
- [5.2 LTS, Jul 2026] New Thin Wall mode in the Principled BSDF (treats the surface as a thin sheet, for paper, leaves, window glass, soap bubbles; also fixes interiors rendering too dark through window glass, and renders faster). New Cycles texture cache (see Q6). EEVEE screen-space ray tracing cleanup and instancing optimizations. — [CG Channel: 5.2 LTS](https://www.cgchannel.com/2026/07/blender-5-2-lts-is-here-discover-its-5-key-features/), [Digital Production](https://digitalproduction.com/2026/07/21/blender-5-2-lts-lands-with-node-physics/), [80.lv](https://80.lv/articles/blender-5-2-lts-has-been-released)

**View transform and color accuracy**
- Khronos PBR Neutral (added as a Blender view transform in 4.2) is designed so output sRGB matches the input base color under grayscale lighting. It targets product photography where HDR values are restricted to small highlights. AgX instead gives about 16.5 stops of range and desaturates highly exposed colors, like film. — [Khronos press release](https://khronos.org/news/press/khronos-pbr-neutral-tone-mapper-released-for-true-to-life-color-rendering-of-3d-products), [Blender 4.2 rendering release notes](https://wiki.blender.org/release_notes/4.2/rendering/), [DevTalk proposal](https://devtalk.blender.org/t/adding-pbr-neutral-tone-mapper/33602)

### Inferences
- For this project's merch (T-shirt/hoodie print colors that must match the Printful design file), Khronos PBR Neutral or Standard is likely the safer view transform than AgX or Filmic. Those desaturate and shift bright colors, which would misrepresent print colors in mockups. This follows from Khronos' stated purpose, but I found no source testing it on printed textiles.
- Bump with Distance around 0.001 m gives a physically sensible millimeter-scale relief. A common beginner failure is leaving the default Distance of 1 m, which makes bumps absurdly strong, so you then turn Strength down. This reasoning follows from the "1 unit = 1 m" fact above.
- If a DirectX normal map shows inverted lighting, invert the green channel before the Normal Map node. This is standard practice, but I could not verify from a fetched page whether Blender's Normal Map node has a native convention toggle. The search summary implied one, which I doubt.

### Gaps
- Could not read the current English Principled BSDF manual page (blocked). Exact defaults and ranges for 5.x inputs (Coat IOR default, Thin Wall options, Sheen defaults) are unverified.
- Could not confirm whether Cycles adaptive subdivision is still behind "Experimental Feature Set" in 5.0 to 5.2. The sources found are 4.1/4.2 manuals.
- Default Dicing Rate values (render and viewport) are not in the retrieved snippets, and no source gave recommended Dicing Scale values for hero shots.
- The "Smart" interpolation mode description in the search summary was garbled ("only for OSL"), so I did not include it as a finding.
- No retrieved source gave explicit guidance on 16-bit vs 8-bit height maps for displacement.

## 2. What separates amateur from professional materials (roughness variation, imperfections, bevels, wear, dust, layers)

### Takeaway
Pro-looking materials get most of their realism from subtle roughness variation (fingerprints, smudges, wipe marks, wear), tiny edge bevels that catch highlights, curvature/cavity-driven wear and dirt, and per-object color variation. The Principled layers (coat, sheen, thin film, anisotropy, SSS) are used sparingly and with intent.

### Cited Findings
**Roughness and surface imperfections**
- A single flat roughness value is a classic tell. Fine grime and fingerprint variation in the roughness channel is recommended, and one source claims "subtle roughness variation does more to sell realism than almost any other single texture". This is opinion from a glossary/marketing page. — [3D glossary: roughness map](https://3d.irpr.agency/glossary/roughness-map/), [Sloyd glossary](https://www.sloyd.ai/glossary/roughness-map)
- Smudges, scratches and fingerprints are independent of color. They can be authored as grayscale maps and fed into roughness/glossiness, bump, anisotropy or reflectivity. Hand smudges and wiping residue add subtle variation to the roughness channel. — [dgruwier surface imperfections](https://dgruwier.gumroad.com/l/surfaceimperfections), [50 tileable roughness maps](https://www.artstation.com/marketplace/p/29Yo/50-tileable-roughness-maps-surface-imperfection), [Poliigon smudges](https://www.poliigon.com/textures/surface-imperfections/smudges)
- Place roughness changes logically. Smooth the surface where it is grabbed or poked and where contact rubs roughness away, and add fingerprints if humans handle the object (forum advice; the summary did not tie it to one page). — [Blender Artists: Desert Eagle thread](https://blenderartists.org/t/desert-eagle-pistol/1221709), [CG Cookie comment page](https://cgcookie.com/comments/387397/replies/new)
- Procedural imperfection tooling: Imperfekt (65+ procedural imperfections in categories dust, edge wear, grunge, scratches, smudges, spatters, fingerprints). Its docs advise combining several imperfections, using low strength for subtlety, and varying mapping methods. Iconprints is a node group that generates fingerprints procedurally and is designed to plug into the roughness path as a passthrough. — [Imperfekt docs](https://blendermarket.com/products/imperfekt/docs), [Iconprints docs](https://blendermarket.com/products/iconprints-procedural-fingerprint-imperfections/docs)
- For glass, fingerprints work better with adjusted color values (a bit of tint/opacity) than as a pure mask. Roughness around 0.01 gives clear glass and around 0.5 frosted. — [Blender glass tutorial roundup (CAD Kenkyujo)](https://cad-kenkyujo.com/blender-glass/), [Glass+ material](https://www.blendswap.com/blend/20226)
- Procedural imperfections can be built from noise textures plus blend masks. — [BlenderNation: procedural surface imperfections](https://www.blendernation.com/2020/11/23/create-procedural-surface-imperfections-in-blender/)

**Bevel node (rounded edges)**
- The Bevel shader node rounds edges in shading only, with no geometry change, like bump. "Slight rounding on edges helps to capture specular highlights that you would also see in the real world." Radius controls bevel width. Samples default to 4 and noise is resolved with more AA samples. The manual calls it "a very expensive shader" that may slow renders by about 20% even in complex scenes, and suggests it mainly for baking or still frames. — [Blender manual: Bevel node (4.2)](https://docs.blender.org/manual/en/4.2/render/shader_nodes/input/bevel.html), [Manual (3.3)](https://docs.blender.org/manual/en/3.3/render/shader_nodes/input/bevel.html)
- Radii like 0.001-0.002 m are the scale the search surfaced for hard-surface edges, but the retrieved source did not state a recommended value. — [iMeshh bevel tutorial page](https://imeshh.com/blog/is-this-the-most-realistic-bevel-method-in-blender-imeshh-tu)
- Known bug: the AO node can fail to respond to beveled edges, so check masks that combine Bevel and AO. — [Blender tracker T90134](https://developer.blender.org/T90134), [T88292](https://developer.blender.org/T88292)

**Edge wear, cavities, dust**
- Wear follows curvature. Convex edges get paint chips, scratches and bright wear. Concave recesses and cavities get dirt and grime. — [StraySpark: procedural edge wear](https://www.strayspark.studio/learn/tutorials/procedural-edge-wear-blender), [80.lv: procedural wear A to Z](https://80.lv/articles/blender-guide-procedural-wear-from-a-to-z)
- Mask sources: the Geometry node "Pointiness" → ColorRamp → Mix between two shaders (historic approach). The Bevel node and the AO node came later and give better edge/cavity masks. — [BlenderNation: better edge and cavity masking](https://www.blendernation.com/2019/02/10/better-edge-and-cavity-masking-with-cycles/), [CG Cookie: edge wear and cavity dirt](https://cgcookie.com/community/10412-procedural-edge-wear-and-cavity-dirt)
- Dust masks use the surface direction (normal pointing up). The setup is Texture Coordinate "Normal" (or Geometry normal) as a mask for dust or bleached areas. Sheen in the 4.0+ Principled model is also suggested for dust on arbitrary materials. — [CG Cookie: edge wear and cavity dirt](https://cgcookie.com/community/10412-procedural-edge-wear-and-cavity-dirt), [Blender 4.0 Shading notes](https://wiki.blender.org/release_notes/4.0/shading/)

**Color variation**
- The Object Info node's Random output gives a per-object-instance random number, usable for color/roughness variation across duplicates. Feed it into a ColorRamp (a range of colors to pick from) or a Noise texture. It only works in material shading nodes. Object Index, Material Index, Location and Color are other outputs. — [Blender manual: Object Info node](https://docs.blender.org/manual/id/4.0/render/shader_nodes/input/object_info.html), [Blender Artists: randomize material per instance in Geometry Nodes](https://blenderartists.org/t/geometry-nodes-randomize-material-on-each-instance/1340135)

**Anisotropy, coat, thin film**
- Principled Anisotropic: positive values stretch highlights along the tangent, negative values perpendicular. Anisotropic Rotation 1.0 is a full circle. The Tangent socket gives extra control, such as random brush orientation. Highly anisotropic brushed sheet metal becomes mostly isotropic at extreme grazing angles. Older docs say anisotropic shading works only in Cycles and only in rendered view. — [Principled BSDF manual (2.91)](https://docs.blender.org/manual/de/2.91/render/shader_nodes/shader/principled.html), [CG Cookie: Tangent vs Anisotropic Rotation](https://cgcookie.com/community/10038-difference-between-tangent-socket-and-anisotropic-rotation), [BlenderNation: anisotropic material (Oct 2025)](https://www.blendernation.com/2025/10/08/how-to-create-anisotropic-material-in-blender/)
- Coat: separate IOR (typically 1.45-1.55 for coats), its own roughness, and its own normal. Keeping base and coat normals separate allows an orange-peel effect on top of a smooth base. Consumer plastics have a thinner molded glossy finish than automotive paint. — [Tripo3D: clearcoat workflows](https://www.tripo3d.ai/blog/explore/hd-model-clearcoat-workflow-for-automotive-and-plastics), [Blender 4.0 Shading notes](https://wiki.blender.org/release_notes/4.0/shading/)

### Inferences
- A practical "pro" roughness stack is a base roughness value plus a low-contrast large-scale noise, plus a fingerprint/smudge map near touch points, plus wear driven by edge masks. This is a synthesis of the above, not a single source's recipe.
- Bevel node on every material is costly (about 20% per the manual), so reserve it for hero assets, or bake it or use real micro-bevels for large scenes.
- Anisotropy likely does not transfer cleanly to EEVEE. The only source says Cycles-only and is an older doc, so verify in 5.x.

### Gaps
- No retrieved source quantified "good" roughness ranges for fingerprints or smudges (for example, a 0.1-0.3 delta). Numeric recipes beyond the Bump Distance case were scarce.
- No Josh Gambrell, Ian Hubert, Default Cube or Blender Guru pages could be fetched. Their specific node setups are not captured here.
- Whether Blender 5.x has a built-in Curvature/edge-detect node (replacing Pointiness/Bevel/AO tricks) was not established.

## 3. Texel density, UV unwrapping, texture resolution, tiling and anti-repetition

### Takeaway
Pick a target texel density (px per meter) first, then derive the texture size. Game-oriented guides use 512-1024 px/m for third person and 1024-2048 px/m for first person, and for close product renders you scale up from there. Hide tiling with stochastic or Voronoi-cell "texture bombing" (random offset/rotation per cell, with blended seams) or with hex tiling. For large surfaces without UVs, use Object/World coordinates.

### Cited Findings
**Texel density and resolution**
- Texel density measures texture pixels per unit of 3D space. A 1K texture covering a 1 m wall is 1024 px/m. Typical targets: 512-1024 px/m for third-person games at 60 FPS, 1024-2048 px/m for first-person. Plan by pixels per meter (a 2 m wall at 512 px/m needs about 1024 px), unwrap to that target, and document exceptions for hero shots, hidden areas, decals and trim sheets. — [Seeles DCC texel density guide](https://www.seeles.ai/features/tools/dcc-texel-density-uv-unwrap-guide), [StraySpark texture resolution guide](https://www.strayspark.studio/blog/texture-resolution-guide-games-512-1k-2k-4k), [Maxon texel density help](https://help.maxon.net/c4d/2026/en-us/Content/html/Texel_Density.html)
- 2K/4K/8K = 2048², 4096², 8192² px; textures are usually square and correspond to one UV tile. — [Blender Artists: what resolution of texture](https://blenderartists.org/t/what-resolution-of-texture-should-i-use-2k-4k-8k-or-can-sbsar-be-used-in-blender/1166226)
- Commercial T-shirt print models ship with 2K maps (base color, normal, roughness, metalness, opacity), while premium mockup scenes advertise roughly 1M polygons and 6K renders with a relief fabric texture. This shows how merch mockups are typically built, but it is vendor marketing. — [Superhive: T-Shirt Print](https://superhivemarket.com/products/t-shirt-print), [Mavvisuals T-shirt mockup](https://mavvisuals.gumroad.com/l/BlenderStudioTshirtMockup)

**UDIMs**
- UDIM tile 1001 is the main tile, 1002 is to its right, and a row is ten tiles wide (1001-1010). UDIMs support 2D and 3D painting. The benefit is painting a head at full 4K while the rest of the body also keeps proportionally high resolution. — [Blender manual: UDIMs (4.2)](https://docs.blender.org/manual/sl/4.2/modeling/meshes/uv/workflows/udims.html), [Garage Farm: UDIMs in Blender](https://garagefarm.net/blog/setting-up-udims-in-blender-step-by-step)

**Anti-repetition / anti-tiling**
- Texture bombing via Voronoi scatter randomizes each repetition and hides seams. It works by manipulating texture vectors, so it does not noticeably increase memory or render time. — [BlenderNation Bazaar listing](https://bazaar.blendernation.com/?p=9752), [Scattershot](https://superhivemarket.com/products/scattershot---procedural-image-texture-scattering--tiling-with-voronoi)
- Stochastic untiling in nodes: chop UVs into random cells (Voronoi), offset the texture per cell, blend cell boundaries, and use a Vector Rotate node to keep normal-map directions aligned when tiles are rotated. — [A23D: seamless textures in Blender](https://www.a23d.co/blog/how-to-make-textures-seamless-blender)
- Hex tiling is based on Heitz and Neyret's stochastic texturing. Mikkelsen's adaptation replaces expensive histogram preservation with a cheap contrast ramp. A Blender Hex Mapping node randomly rotates hex tiles and blurs their edges, and works in EEVEE and Cycles. — [Godot Shaders: Mikkelsen adaptation](https://godotshaders.com/shader/stochastic-hex-tiling-mikkelsens-adaptation/), [Hex Mapping (Superhive)](https://superhivemarket.com/products/hex-mapping), [DevTalk: Stochastic texturing](https://devtalk.blender.org/t/stochastic-texturing/17032)
- The cheap alternative "tiling texture fixer" computes the average color and applies a high-pass-like filter, then recombines, to reduce visible repetition. — [Tiling Texture Fixer](https://sanderwit.gumroad.com/l/tiling-texture-fixer)
- Procedural materials with Object coordinates (instead of UV) avoid UV dependence. A rust example used Mapping with Object coordinates and a Noise Texture bump (Scale 3, Detail 12). — [BlenderNation Bazaar: procedural rusted metal](https://bazaar.blendernation.com/listing/making-a-procedural-rusted-metal-material/)
- A commercial "World Space Texture Mapping" add-on provides one-click triplanar materials with no UVs. — [Superhive](https://superhivemarket.com/products/world-space-texture-mapping-one-click-triplanar-materials-no-uvs-required)

### Inferences
- For close-up product shots, a target of 1024-2048 px/m is the floor, not the ceiling. The game numbers above assume a camera that rarely gets within a few cm of a surface. A T-shirt print hero shot may justify 4K-8K on the print area only (UDIM or a separate print texture).
- For fabric weave on a garment, a tiled weave texture at world-scale (real-world threads of roughly 0.3-1 mm) plus a separate non-tiling print layer is the usual structure. Tile the weave with anti-repetition and keep the print on unique UVs. This is my synthesis, not a cited recipe.

### Gaps
- Blender-native box/triplanar projection (the Image Texture node's "Box" projection with Blend) was not confirmed from a fetched Blender source. The triplanar results returned were Octane/Redshift docs, which are a different renderer.
- Blender's Texel Density add-on, or the 4.x/5.x UV-editor features for texel density, were not found in the retrieved results.
- No Blender-specific guidance on UV island padding or margin values (px at 2K/4K/8K) was retrieved.
- No source covered the Image Texture "Box" blend value, or whether recent versions added a native stochastic/anti-tiling option.

## 4. Procedural vs image-based texturing, Geometry Nodes, baking, and Substance/Mixer interplay

### Takeaway
Use image scans or authored maps for hero close-ups and recognizable detail, and procedurals for infinite resolution, low memory, variation and breakup. The strongest results combine both (an image base plus procedural roughness, wear and variation). Baking in Cycles (high-to-low normal, AO, etc.) and Substance Painter's Blender export template make the handoff straightforward. Quixel Mixer is discontinued as of Feb 2026.

### Cited Findings
- Procedural textures need no unwrapping, but are harder to control than images. The advice is to use them for broad strokes and as a foundation for base surface texture. — [O'Reilly: Blender for Dummies, procedural textures](https://www.oreilly.com/library/view/blender-for-dummies/9780470584460/ch008-sec002.html) (older book, general principle)
- Procedural concrete claims: low memory, unlimited detail that scales without loss, seamless with no visible repeats, easy customization. Built by overlaying Noise, Voronoi, Musgrave and Wave textures. Scanned concrete wins in extreme close-ups, with real porous structure, aggregate breakouts and damage, and uses normal, height and roughness maps. — [Superhive: procedural concrete](https://superhivemarket.com/products/procedural-concrete--asphalt-plaster-material), [CGTrader scanned concrete](https://www.cgtrader.com/3d-models/textures/architectural-textures/broken-cracked-rough-concrete-surface)
- Cycles baking: rays are cast from the low-poly object inward toward the high-poly object. Use Max Ray Distance (no cage) or Extrusion (with cage) to tune ray start. A cage is a ballooned-out version of the low-poly mesh (automatic or a manual cage object). Without a cage, rays follow the mesh normals, which can glitch on edges but suits baking into planes. Tangent space is the default for normal maps and the right choice in most cases, because maps then work for deformed or animated objects. — [Blender manual: Render Baking (5.0)](https://docs.blender.org/manual/en/5.0/render/cycles/baking.html), [Manual (5.1)](https://docs.blender.org/manual/en/5.1/render/cycles/baking.html), [Manual (4.0)](https://docs.blender.org/manual/nb/4.0/render/cycles/baking.html)
- Substance 3D Painter → Blender: use the "Blender (Principled BSDF)" export template (OpenGL normal). Then apply all maps at once with Blender's Node Wrangler, or use bridge add-ons that build a Principled material per texture set and pull maps back automatically. — [Blender Artists thread](https://blenderartists.org/t/substance-painter-and-blender/1507370), [DigiKrafting add-on](https://github.com/DigiKrafting/blender_addon_substance_painter), [Substance Painter Bridge FAQ](https://superhivemarket.com/products/substance-painter-bridge/faq)
- Quixel Mixer: Epic released Mixer 2023.1 in Feb 2026 as the final version, free, with no further updates or support, online functionality removed, and it keeps running offline. — [CG Channel: Mixer discontinued](https://www.cgchannel.com/2026/02/quixel-mixer-has-been-discontinued-get-the-final-version-for-free/)
- Megascans moved to paid on Fab in 2025 (reported prices start at $0.99 for 2D/3D assets, $4.99 for procedural kits, $24.99 for packs). Legacy Megascans access is discussed on the Epic forums. — [CG Channel (Oct 2024)](https://www.cgchannel.com/2024/10/epic-games-has-made-megascans-free-to-all-but-only-until-the-end-of-2024/), [Epic forums: legacy Megascans](https://forums.unrealengine.com/t/access-legacy-megascans-on-bridge-and-quixel-com/2142664)
- Geometry Nodes can drive per-instance material variation (for example, randomizing materials per instance), and the Object Info node's Random output serves shader-side variation. — [Blender Artists: randomize material per instance](https://blenderartists.org/t/geometry-nodes-randomize-material-on-each-instance/1340135), [Blender manual: Object Info](https://docs.blender.org/manual/id/4.0/render/shader_nodes/input/object_info.html)
- Blender 5.2 LTS adds online asset libraries (alongside node-based physics). Details on texture sources were not in the retrieved snippets. — [Linuxiac: Blender 5.2 LTS](https://linuxiac.com/blender-5-2-lts-released-with-node-based-physics-and-online-asset-libraries/)

### Inferences
- A good hybrid pattern: keep the scanned or authored base color/normal, then multiply procedural noise into roughness and a faint hue/value shift into base color to break up the "one image repeated" look. The sources support the components (procedural for variation, images for detail), but I found no single page prescribing this combination.
- Substance Painter or Designer is most worth the cost for painted hero assets (hand-painted wear, trim, decals) and for authoring tileable materials. Blender procedurals are enough for most generic surfaces. This is a judgment call and not cited.
- Given Mixer's discontinuation, an alternative for blending scanned materials is Blender's own node-based layering, or Substance 3D Painter/Designer.

### Gaps
- No retrieved source covered Blender 5.x Geometry Nodes features specific to texturing (for example, sampling images in GN or baking GN attributes to textures).
- I could not retrieve Poly Haven's blog/docs, so the "free CC0 PBR source" claim and its map conventions (for example, what Poly Haven provides: nor_gl vs nor_dx, displacement, AO) are not documented here.
- Substance 3D Designer and Painter current licensing and Blender integration status (Adobe docs) were not retrieved.
- No source established what a "Blender Principled BSDF → Substance" round trip looks like in current Adobe docs, or whether Adobe ships an official Blender plugin.
- No source for baking specifics like margin pixel values or AO sampling counts.

## 5. Specific material types (wood, brushed metal, fabric/T-shirts/hoodies, paper/print, glass, plastic, fiberglass/boats, concrete)

### Takeaway
Fabric reads through sheen (microfiber model), a weave normal/height map, and thickness cues. Brushed metal needs anisotropy plus a stretched-noise roughness/bump. Wood needs grain-aligned roughness variation. Glass and paper benefit from the new Thin Wall mode in 5.2. Fiberglass/gelcoat is a glossy pigmented coat with subtle low-frequency waviness. Concrete is a mix of procedural breakup and scanned detail.

### Cited Findings
**Fabric (T-shirts, hoodies)**
- Sheen is the Principled layer for fabric. It models tiny surface fibers and gives a soft velvet-like reflection near edges (Sheen Weight 0-1, Roughness 0-1, Tint). It combines with a fairly high base roughness. — [Principled BSDF manual (4.0)](https://docs.blender.org/manual/zh-hans/4.0/render/shader_nodes/shader/principled.html), [Blender 4.0 Shading notes](https://wiki.blender.org/release_notes/4.0/shading/)
- Weave systems output a normal map plus height for displacement. Examples: Weave Engine (Cycles and EEVEE), a procedural cloth material with per-thread displacement/roughness/normal and a per-thread vector color map, HR-Fabric Materials (42 textile materials with adjustable normal strength and displacement thickness), and a Fabric Weave Generator exporting Albedo, Normal, Roughness, Height and AO. — [Weave Engine](https://superhivemarket.com/products/weave-engine), [Procedural Cloth Fabric Material](https://blendermarket.com/products/procedural-fabric-material), [HR-Fabric Pro](https://superhivemarket.com/products/dt-00014---hr-fabric-materials-pro42), [Fabric Weave Generator](https://mikewall-fcsehbem.on-forge.com/tools/fabric-weave-generator)
- Merch-mockup tools emphasize that the print should follow garment folds and that fleece texture should show through the ink (a design-generator marketing claim). Premium Blender mockup scenes use a relief fabric texture with perfect seams. — [DreamPixelForge hoodie mockup](https://www.dreampixelforge.com/tools/hoodie-mockup), [Mavvisuals T-shirt mockup](https://mavvisuals.gumroad.com/l/BlenderStudioTshirtMockup)

**Wood**
- Roughness maps can vary so grain lines are rougher than the smooth areas between them. Procedural wood systems combine directional grain, growth rings, knots, recessed gaps, worn edges and localized weathering. Pack parameters include scale, rotation, color, detail, distortion, noise, roughness, normal/bump and displacement. EEVEE has limitations with displacement. — [CGAxis: wood PBR in Blender](https://cgaxis.com/wood-pbr-materials-in-blender/), [Superhive: 3 Procedural Wood Materials](https://superhivemarket.com/products/pro-wood), [Rs Procedural Wood](https://superhivemarket.com/products/rs-procedural-wood), [Blender Artists: Believable procedural wood in Cycles](https://blenderartists.org/t/believable-procedural-wood-in-cycles/613323)

**Brushed metal**
- Procedural recipe: a Noise Texture stretched by scaling one axis in a Mapping node, used as the factor of a Mix to modulate color/roughness. Use anisotropy (with the Tangent socket for orientation) plus a glossy layer mix for a hazy appliance-sheet look. Radial brushing needs a custom tangent. — [BlenderNation Bazaar: procedural metal](https://bazaar.blendernation.com/?p=14849), [Blender Artists: procedural brushed metal shader](https://blenderartists.org/t/procedural-brushed-metal-shader-help/678876), [Blender 4 anisotropic metal issue (GameDev.tv)](https://community.gamedev.tv/t/i-cannot-make-anisotropic-metalic-brush-effect-to-work-in-blender-4/238416)

**Glass**
- Default IOR 1.45 suits most glass, and crown glass (windows, glassware) is about 1.52. Roughness 0.01 gives clear glass, 0.5 frosted. Dirty glass is built from layered dirt, scratches, fingerprints and mold. The Light Path node can be used to reduce noise (Glass+ ships configured that way), and the new Thin Wall mode (5.2) makes window glass render faster and avoids dark interiors. — [Blender glass tutorial roundup](https://cad-kenkyujo.com/blender-glass/), [Glass+ material](https://www.blendswap.com/blend/20226), [CG Channel: Blender 5.2 LTS](https://www.cgchannel.com/2026/07/blender-5-2-lts-is-here-discover-its-5-key-features/)

**Plastic**
- Coat IOR typically 1.45-1.55 with separate coat roughness and normals, and orange peel done via a fine normal in the base coat. Consumer plastics have thin molded glossy finishes versus automotive paint. Subsurface is generally treated as either off or on (0 or 1), not partial. — [Tripo3D: clearcoat for automotive and plastics](https://www.tripo3d.ai/blog/explore/hd-model-clearcoat-workflow-for-automotive-and-plastics), [Principled BSDF manual (older versions)](https://docs.blender.org/manual/id/3.0/render/shader_nodes/shader/principled.html)

**Paper and printed matter**
- Paper roughness is about 0.7-0.9, with a low SSS radius and subtle subsurface color for backlit translucency. Fiber detail uses Noise or Voronoi into a Bump node at a very low Strength (about 0.01-0.05). Ink and coating add a tiny sheen, with the paper mottled all over and most visible where ink/coating sits. [low confidence] The numeric values come from a summary referencing uncertain-quality pages, so validate them. The ink-sheen note is from a forum thread. — [Blender Artists: Emulate paper texture](https://blenderartists.org/t/emulate-paper-texture/1489496), [Elephorm: SSS in Blender](https://www.elephorm.com/tuto-blender/translucidite-sss)
- Blender 5.2's Thin Wall mode is explicitly aimed at paper, leaves and window sheets. — [CG Channel: Blender 5.2 LTS](https://www.cgchannel.com/2026/07/blender-5-2-lts-is-here-discover-its-5-key-features/)

**Boats / fiberglass (gelcoat)**
- Gelcoat is a pigmented, glossy protective layer on fiberglass hulls, typically 0.5-0.8 mm thick, usually epoxy or unsaturated polyester based. The inside surface is rough and irregular. — [Wikipedia: Gelcoat](https://en.wikipedia.org/wiki/Gelcoat), [Olympus gelcoat measurement](https://olympus-ims.com/kr/applications/measurement-fiberglass-gelcoat)

**Concrete**
- Procedural concrete is typically Noise + Voronoi + Musgrave + Wave overlays, with controls for aggregate size, roughness, color variation, cracks and stains. Scanned concrete adds real pores and aggregate and holds up in extreme close-ups. — [Superhive: procedural concrete](https://superhivemarket.com/products/procedural-concrete--asphalt-plaster-material), [CGTrader](https://www.cgtrader.com/3d-models/textures/architectural-textures/broken-cracked-rough-concrete-surface), [Superhive: Architectural Concrete Pack](https://superhivemarket.com/products/architectural-concrete-pack)

### Inferences
- For printed T-shirts and hoodies the realistic structure is probably two layers. One is a fabric base (weave normal/height, sheen, high roughness, subtle fiber noise). The other is a print layer (ink color, slightly different roughness and a faint raised edge) blended on top, with the fabric normal still showing through the ink. This matches the "fleece texture shows through the ink" idea but is my synthesis. Printful's own mockups are likely a good reference for the target look.
- For boats/gelcoat, a plausible Principled setup is a pigmented base with a Coat layer (IOR about 1.5), low base roughness (about 0.1-0.2), and a very low-frequency waviness normal to avoid CG-perfect surfaces. Plus subtle chalking/oxidation roughness variation and scuffs on edges. No Blender-specific gelcoat source was found, so these values are unsourced starting points.
- For wood grain, aligning roughness and bump variation with the grain direction (stretched noise or a wave-based grain driving both) is the common pattern, and it also fits the carpentry context. Sources describe grain-linked roughness but not exact node values.

### Gaps
- No Blender-specific gelcoat/fiberglass tutorial or numeric roughness values were found. Only general gelcoat facts.
- No verified numeric recipe for cotton jersey or fleece in Principled terms (Sheen Weight/Roughness/Tint, base roughness), only qualitative guidance and commercial packs.
- No source describing how DTG (direct-to-garment) or screen-print ink actually looks (gloss, edge height) for rendering purposes.
- The wood and paper findings rely on commercial pack pages and a forum thread. No major-creator (Blender Guru, Ian Hubert, Default Cube, Josh Gambrell) walkthrough could be fetched.
- The paper numbers are low confidence (see above).

## 6. Common mistakes and performance/memory tips

### Takeaway
The big avoidable mistakes are wrong color spaces on data maps, wrong normal-map convention, oversized textures, bump/displacement units, and expensive shader features (Bevel node, true displacement) left on everywhere. In 5.2 LTS, the Cycles texture cache offers a way to cut VRAM use for texture-heavy scenes.

### Cited Findings
**Common mistakes**
- Roughness/Metallic/normal maps left in sRGB instead of Non-Color. — [uhiyama-lab](https://uhiyama-lab.com/en/notes/blender/materials-shading-pbr-workflow/), [StraySpark](https://www.strayspark.studio/learn/tutorials/set-up-strayspark-pbr-materials-blender), [cgbookcase](https://www.cgbookcase.com/learn/how-to-use-pbr-textures-in-blender)
- Using a DirectX normal map in Blender (inverted bumps/dents). — [CGAxis](https://cgaxis.com/which-normal-map-should-i-use-opengl-or-directx/)
- Using only the default bump distance (1 unit = 1 m) for fine detail instead of values around 0.001. — [Blender Artists: Bump Distance](https://blenderartists.org/t/should-bump-node-distance-ever-really-be-higher-than-0-001/1418023)
- True displacement on a mesh that is not subdivided enough. — [Blender manual: Displacement node](https://www.blender.org/manual/en/render/shader_nodes/vector/displacement.html)
- Perfectly sharp edges and flat roughness (no Bevel/roughness variation). — [Blender manual: Bevel node](https://docs.blender.org/manual/en/4.2/render/shader_nodes/input/bevel.html), [3D glossary](https://3d.irpr.agency/glossary/roughness-map/)

**Performance / memory**
- Textures are almost always the largest memory consumer, followed by dense geometry. Halving a few oversized textures often frees more memory than any other single change. A single 8K texture can take a large share of VRAM. Suggested budget: hero textures 4K, background textures 2K. Cycles can spill into system RAM (out-of-core). The source also recommends enabling texture compression/limits in render settings. The source is a general hardware-retailer tip article, so treat it as medium-low confidence. — [Evetech: fix out-of-VRAM in Blender](https://evezone.evetech.co.za/quick-bytes/how-to-fix-out-of-vram-errors-when-rendering-a-scene-in-blender), [OptiMem listing](https://blendermarket.com/products/optimem)
- [5.2 LTS] Cycles texture cache: Blender generates an optimized .tx file for each image texture (placed in a "blender_tx" folder beside the source image), stored tiled and multi-resolution. Cycles then loads only the tiles and mip levels the frame needs instead of the full image. Reduces memory use and startup time. Trade-off is extra disk use and a small render performance cost. — [Digital Production: 5.2 LTS targets texture-heavy renders](https://digitalproduction.com/2026/05/12/blender-5-2-lts-targets-texture-heavy-renders/), [CG Channel: 5.2 LTS](https://www.cgchannel.com/2026/07/blender-5-2-lts-is-here-discover-its-5-key-features/), [Labmemo](https://labmemo.com/?p=53740)
- [5.1] EEVEE uses less memory via more efficient texture handling, and shader compilation is 25-50% faster. — [CG Channel: Blender 5.1](https://www.cgchannel.com/2026/03/discover-5-key-features-in-blender-5-1)
- Bevel node can slow a render by about 20%, so prefer it for baking or stills. — [Blender manual: Bevel node](https://docs.blender.org/manual/en/4.2/render/shader_nodes/input/bevel.html)
- Adaptive subdivision turns shared (multi-user) mesh data into single-user data (more memory), and does not tessellate instances individually. — [Manual: Adaptive Subdivision (4.1)](https://docs.blender.org/manual/en/4.1/render/cycles/object_settings/adaptive_subdiv.html)
- Texture bombing and vector-based anti-tiling add no noticeable memory or render-time cost versus larger textures. — [BlenderNation Bazaar](https://bazaar.blendernation.com/?p=9752)
- Procedural materials are low-memory but cost render time. This is the trade-off against image textures. — [Superhive: procedural concrete](https://superhivemarket.com/products/procedural-concrete--asphalt-plaster-material)

### Inferences
- With Cycles texture cache available in 5.2 LTS, the "downsize everything to 2K/4K" rule is somewhat relaxed for texture-heavy scenes. But the cache costs disk and a little speed, so it matters most when VRAM is the limit. For a single product shot with one or two garments, VRAM is unlikely to be the constraint, and print/hero textures can stay at 4K-8K.
- Bake expensive procedural + Bevel node setups to textures for assets reused across many renders (a product turntable, for instance). Bake once, render many.

### Gaps
- No retrieved source gave measured VRAM numbers per texture resolution, or the exact UI path and default of the Simplify Texture Limit setting.
- No data on whether 8-bit PNG vs 16-bit PNG/EXR matters for displacement and roughness in current Cycles.
- The exact 5.2 texture-cache enable path (Render Properties location, defaults) was not retrieved.
- Denoising, light-path, sampling and adaptive-sampling settings related to texture noise (fireflies from glossy/clear coat) were not researched.
