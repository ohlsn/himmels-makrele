## 1. Blender glTF/GLB exporter: settings, Principled BSDF mapping, extensions, gotchas

### Takeaway
Blender's official glTF 2.0 add-on exports core metal-rough PBR plus a broad extension set (clearcoat, transmission, volume, sheen, specular, IOR, anisotropy, dispersion, iridescence, emissive_strength, texture_transform, unlit, GPU instancing, Draco, Meshopt). It only exports what is reachable through Image Texture nodes or constant values on Principled BSDF inputs, so Cycles procedural networks must be baked first, and several defaults (PNG images, no mesh compression, Apply Modifiers off) need changing for web delivery.

### Cited Findings

**Versions**
- The add-on on the `main` branch is version 5.3.36 and declares a minimum Blender of 5.3.0, so the manual text quoted below describes the newest (5.3-era) add-on; option availability in earlier 4.x/5.0-5.2 releases may differ — [glTF-Blender-IO __init__.py](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/addons/io_scene_gltf2/__init__.py)
- Blender 5.0's exporter reportedly gained better Draco defaults and KHR_materials_variants; 5.2 added EXT_meshopt_compression / KHR_meshopt_compression; 5.3 added animation-pointer export for custom properties and node-tree performance work (snippet-only summary of Blender release notes; a blog says 5.0 promoted glTF to the recommended path for static game assets) — [Blender 5.3 pipeline/IO release notes (snippet)](https://developer.blender.org/docs/release_notes/5.3/pipeline_io/); [Cinevva Blender 5 guide (secondary blog)](https://app.cinevva.com/guides/blender-5-for-game-artists)

**Supported extensions (Blender manual, `main`)**
- Export list: KHR_draco_mesh_compression, KHR_lights_punctual, KHR_materials_clearcoat, KHR_materials_transmission, KHR_materials_unlit, KHR_materials_emissive_strength, KHR_materials_volume, KHR_materials_sheen, KHR_materials_specular, KHR_materials_anisotropy, KHR_materials_dispersion, KHR_materials_ior, KHR_materials_variants, KHR_texture_transform, EXT_mesh_gpu_instancing, EXT_meshopt_compression, KHR_meshopt_compression, KHR_animation_pointer — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Inconsistency inside the same manual: the extension list above omits KHR_materials_iridescence, yet the Materials section says "Iridescence can be exported using the KHR_materials_iridescence extension" (Thin Film IOR socket -> iridescence IOR; Principled "thickness" socket -> factor; max thickness via the custom `glTF Material Output` group node; factor texture in R, thickness texture in G) — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Import list additionally includes KHR_materials_pbrSpecularGlossiness and KHR_mesh_quantization — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Third-party add-ons can add support for extra glTF extensions without modifying the official add-on (example-addons folder in the repo) — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)

**Principled BSDF -> glTF mapping**
- Core channels: Base Color (value, RGB node, or Image Texture), Metallic and Roughness (values 0-1, or textures read from B and G channels), Normal (must go through a Normal Map node in default Tangent Space; strength copied; +Y up), Emission, and baked Occlusion — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Normal map: Image Texture (Color Space Non-Color) -> Normal Map node -> Principled Normal. "Tangent Space ... is the only type of normal map currently supported by glTF"; the exporter does not export these nodes but uses them to find the image — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Occlusion has no Principled equivalent: the exporter looks for a custom node group named `glTF Material Output` with an `Occlusion` input holding an Image Texture (add via Add > Output > glTF Material Output after enabling "Shader Editor Add-ons" in preferences). The effect need not be visible in Blender. glTF stores occlusion in R, so it can share one image with roughness (G) and metallic (B) — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- If any emissiveFactor component is > 1.0 the exporter adds KHR_materials_emissive_strength — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Clearcoat: exported when the Clearcoat input is nonzero or textured (KHR_materials_clearcoat), with optional clearcoat roughness and clearcoat normal — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Sheen: sheen roughness texture must be written to the alpha (A) channel; the Sheen BSDF node is only available in Cycles (switch engine temporarily to add it) — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Specular: KHR_materials_specular is exported when Specular IOR Level or Specular Tint are non-default or textured — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Transmission: not alpha blending; keep alpha mode Opaque unless the material only partially covers the geometry. Refraction needs KHR_materials_transmission plus KHR_materials_volume. Manual warns transmission "is complex for real-time rendering engines ... support is not yet widespread" and transmissive materials may not be visible behind other transmissive materials — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Volume: exported from a Volume Absorption node linked to the Output's Volume socket, only if some transmission is set; node color = attenuation color (no texture allowed), density = inverse attenuation distance; thickness via the `glTF Material Output` group (texture in G channel) — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- IOR: exported only when KHR_materials_transmission, _volume or _specular is also used, and not exported when equal to the glTF default 1.5 — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- KHR_texture_transform comes from a Mapping node attached to an Image Texture; "Point" mapping type recommended; supported: Location X/Y, Rotation Z only, Scale X/Y — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Only Metal/Rough PBR (core glTF) and Shadeless (KHR_materials_unlit) materials are supported; other shader setups are not exported as such (manual statement, as summarised by fetch tool) — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)

**Exporter options and defaults (source code of the operator)**
- Draco: compression level default 6 (property range 0-10; description "0 = most speed, 6 = most compression, higher values currently not supported"); quantization bits defaults: position 14, normal 10, texcoord 12, color 10, generic 12 (range 0-30) — [Blender-IO __init__.py](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/addons/io_scene_gltf2/__init__.py). The manual only says higher level = slower encode/decode and higher bits = better compression rate (conflicts mildly in wording with the code description) — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Meshopt: `export_meshopt_compression_enable` default False; extension default `EXT_meshopt_compression`, alternative `KHR_meshopt_compression` — [Blender-IO __init__.py](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/addons/io_scene_gltf2/__init__.py)
- Images enum: Automatic (default), JPEG, WebP, None; JPEG quality default 75; "Image Quality" default 75; options "Create WebP" (extra WebP alongside existing), "WebP fallback" (PNG fallback), "Keep Original" (default off); no AVIF choice exists. Manual: PNG lossless is generally preferred but "JPEG might be preferable for web applications due to the smaller file size"; choosing WebP saves all textures as WebP with no PNG/JPEG fallback — [Blender-IO __init__.py](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/addons/io_scene_gltf2/__init__.py); [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- `+Y Up` default True — [Blender-IO __init__.py](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/addons/io_scene_gltf2/__init__.py)
- Apply Modifiers default False; description: "Apply modifiers (excluding Armatures) to mesh objects - WARNING: prevents exporting shape keys" — [Blender-IO __init__.py](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/addons/io_scene_gltf2/__init__.py)
- Mesh data: UVs, Normals, Tangents toggles; custom Attributes only exported if the name starts with an underscore; loose edges/points exported as lines/points using the first material slot; "Shared Accessor" makes triangle index sharing smaller with many materials — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Vertex colors: modes Material (default; exports only when used as Base Color multiplier, "most accurate regarding glTF specification"), Active, Name, None — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Materials mode: Export / Placeholder / Viewport / No Export (No Export merges primitives and loses material slots; Placeholder keeps slots) — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Shape keys: export toggle plus separate Shape Key Normals / Tangents; "Use Sparse Accessor if better" (saves space if file smaller); "Omitting Sparse Accessor if data is empty" off by default because "not all viewers managed it correctly" — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Skinning: "Bone influences" - models may display incorrectly in many viewers with values other than 4 or 8 — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Animation: modes Actions (default), Active Actions Merged, NLA Tracks, Scene; sampling applied by default (disabling can cause export errors); "Optimize Animation Size" removes duplicate keyframes; shape-key animation needs shape-key export enabled; KHR_animation_pointer (material/light/camera property animation) is marked experimental; shape key animation driven by drivers requires the mesh to be a direct armature child (manual statements, as summarised by fetch tool) — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst); [Blender-IO __init__.py](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/addons/io_scene_gltf2/__init__.py)
- Lighting Mode (for exported lights): Standard (physical cd/lx/nt), Unitless, Raw (deprecated) — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- GPU instancing export (EXT_mesh_gpu_instancing) option exists; constraints per manual summary: instances must be meshes without children, share the same parent, and cannot vary per-instance material — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst); [Blender-IO __init__.py](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/addons/io_scene_gltf2/__init__.py)
- Geometry is always triangulated (quads/ngons converted); discontinuous normals/UVs are stored as split vertices so glTF vertex counts exceed Blender's; non-mesh data (curves) must be converted; UDIM textures are split per tile — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- File variants: .glb binary, .gltf + .bin + textures, and embedded base64 .gltf (the least efficient) — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)

**Consumer side (three.js GLTFLoader, current master)**
- GLTFLoader supports: KHR_draco_mesh_compression, KHR_lights_punctual, KHR_materials_anisotropy, _clearcoat, _dispersion, _emissive_strength, _ior, _iridescence, _sheen (present in code), _specular, _transmission, _unlit, _volume, KHR_mesh_quantization, KHR_meshopt_compression, EXT_meshopt_compression, KHR_texture_basisu, KHR_texture_transform, EXT_materials_bump, EXT_mesh_gpu_instancing, EXT_texture_webp, EXT_texture_avif. Supported only via separately registered plugins: KHR_gaussian_splatting, KHR_materials_variants (three-gltf-extensions), KHR_animation_pointer (needle-tools), NEEDLE_progressive — [three.js GLTFLoader.js](https://raw.githubusercontent.com/mrdoob/three.js/master/examples/jsm/loaders/GLTFLoader.js)
- GLTFLoader no longer feature-detects WebP/AVIF (r175 -> r176 migration note) — [three.js Migration Guide](https://raw.githubusercontent.com/wiki/mrdoob/three.js/Migration-Guide.md)
- KHR_materials_pbrSpecularGlossiness support was removed from GLTFLoader/GLTFExporter (older assets must be converted to metal/rough) — [three.js Migration Guide](https://raw.githubusercontent.com/wiki/mrdoob/three.js/Migration-Guide.md)

### Inferences
- Because Blender cannot export AVIF and only produces WebP/JPEG/PNG, the sane split is: export from Blender with Images = Automatic (or PNG) from lossless sources, and do all final texture encoding (KTX2, WebP, AVIF) in glTF Transform afterwards. Re-encoding a JPEG exported at quality 75 into KTX2 would stack two lossy passes (the Khronos KTX guide recommends PNG sources; see section 3).
- Blender's built-in Draco/Meshopt is convenient for quick exports, but glTF Transform's `copy` strips Draco and `weld`/`simplify`/`join` need uncompressed geometry (see section 3), so for a pipeline with post-processing it is cleaner to export uncompressed and compress last.
- Suggested export checklist (inference from the above): Format = glTF Binary (.glb); +Y Up on; Apply Modifiers on only for meshes without shape keys (otherwise apply modifiers destructively on a duplicate first); Materials = Export; Vertex Color = Material unless vertex AO is deliberately baked to colors; Cameras/Lights/Custom Properties off unless needed; keep Bone influences at 4; shape key normals/tangents off unless lighting looks wrong on morph targets; Lighting Mode = Standard only if exporting lights.
- Material features that render consistently in three.js and are exported by Blender: clearcoat, sheen, specular, IOR, volume, transmission, emissive_strength, anisotropy, dispersion, iridescence, texture_transform. Transmission/volume are the most expensive on mobile (extra scene render pass in three.js; this performance point is general knowledge and not sourced here) and the Blender manual itself flags limited engine support.

- docs.blender.org and developer.blender.org were blocked, so release notes for Blender 4.2 LTS / 4.5 LTS / 5.0 / 5.1 / 5.2 / 5.3 glTF changes could not be read directly; per-version availability of Meshopt, WebP, iridescence, etc. is unverified (only the 5.x summary above, from a search snippet and a blog).

## 2. Baking pipeline: Cycles shader networks, AO/lightmaps, atlasing, ORM packing, normal maps, environment lighting

### Takeaway
Blender's own glTF docs prescribe the Cycles Bake panel for AO and for tangent-space normal maps, plus the R=occlusion / G=roughness / B=metallic packing and the `glTF Material Output` node for occlusion. Atlasing/merging is done after export with glTF Transform `palette` and `join`. Baking full lighting or environment lighting into textures is possible but is not covered by a primary source; glTF only has an occlusion slot, so baked lighting normally goes into base color on an unlit material.

### Cited Findings
- Cycles Bake panel can bake ambient occlusion; the saved image is connected directly to the `glTF Material Output` Occlusion input — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Cycles Bake panel can bake tangent-space normal maps "from almost any other arrangement of normal vector nodes": set Bake type to Normal, keep default space settings (Tangent; R +X, G +Y, B +Z), save the image, plug it into a new material through a Normal Map node (Non-Color) so it exports — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- ORM packing as glTF defines it: occlusion R, roughness G, metallic B; Blender node recipe: Image Texture (Non-Color) -> Separate RGB -> G to Roughness, B to Metallic, R to the occlusion group input — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Manual rationale for baked AO: useful for real-time viewers "particularly on platforms where there may not be spare power for computing such things at render time" — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Blender "Selected to Active" bake: rays are cast from the low-poly object inward toward the high-poly object; if the high-poly mesh is not fully enclosed, adjust Ray Distance (no cage) or Cage Extrusion (with cage); a custom cage object requires identical topology (face count and order); Margin extends the baked result N pixels beyond UV islands to soften seams (snippet-only summary, consistent across manual versions 2.90, 2.91, 4.1, 4.5) — [Blender manual: Render Baking 2.90](https://docs.blender.org/manual/en/2.90/render/cycles/baking.html); [Blender manual: Render Baking 4.5](https://docs.blender.org/manual/ar/4.5/render/cycles/baking.html)
- Khronos 3D Commerce guideline ranks the standard maps by priority: Base Color, ORM, Normals, Emissive — [Khronos 3DC Publishing Targets](https://raw.githubusercontent.com/mlimper/3DC-Asset-Creation/main/asset-creation-guidelines/full-version/sec99_PublishingTargets/PublishingTargets.md)
- KTX artist guidance relevant to baked output: start from 8-bit uncompressed PNG (JPEG artifacts get amplified by block compression); align UVs along 4x4 pixel block boundaries; apply texture dilation and minimize UV seams; consider upscaling 512 -> 1024 before compression to reduce artifacts while keeping size benefits — [Khronos KTX Artist Guide](https://raw.githubusercontent.com/KhronosGroup/3D-Formats-Guidelines/main/KTXArtistGuide.md)
- Texture atlas / material merging tooling: glTF Transform `palette` builds palette textures from scalar-only material values (base color, alpha, emissive factor, metallic factor, roughness factor), merges those materials and so enables more `join` operations; defaults block size 4 px, min 5 blocks; materials that already use UVs/textures are not eligible — [glTF Transform CLI source](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/cli/src/cli.ts); [palette.ts](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/functions/src/palette.ts)
- glTF Transform `join` reduces draw calls (requires `flatten`); `unlit` converts materials to an unlit, shadeless model that "can be rendered very efficiently on less capable mobile devices" — [glTF Transform CLI source](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/cli/src/cli.ts)
- Blender supports Shadeless export through KHR_materials_unlit (manual: unlit materials are built by mixing under camera-ray, without a Principled BSDF) — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)
- Blender exports UDIM textures split into per-tile images (must share one UV map); a single-atlas workflow is therefore preferable for web — [Blender glTF manual source](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst)

### Inferences
- Recommended bake recipe (rule-of-thumb numbers are practitioner conventions, not from a fetched source; adjust by testing):
  1. Unwrap one non-overlapping UV layout per object (or per atlas group) with consistent texel density; keep a margin so that mip levels do not bleed (rough guide: 8-16 px margin at 2048, 4-8 px at 1024).
  2. Bake in Cycles with Selected to Active: low-poly active, high-poly selected, cage (or extrusion/ray distance) tuned until no rays miss; bake Normal as Tangent (Non-Color, default +X +Y +Z) at 2048 for hero parts, 1024 otherwise.
  3. Bake albedo with only the Color pass (no direct/indirect) so lighting is not baked into base color; bake Roughness and Metallic via the Emit-based trick or Principled passes into single-channel images, AO via the AO bake type, then pack R=AO, G=Roughness, B=Metallic into one ORM image (compositor/Python/Image Texture + Separate/Combine RGB), saved as 8-bit PNG, Non-Color.
  4. Wire the packed image as in the manual (G -> Roughness, B -> Metallic, R -> `glTF Material Output` Occlusion); base color as sRGB, everything else Non-Color.
  5. Keep source EXR/PNG bakes outside the deployed repo (the project's CLAUDE.md already excludes `.psd` through `.vercelignore`/`.gitignore`; the same treatment would suit `.blend` files, high-poly sources and large bake PNGs).
- If the design requires the full Cycles look (GI, caustics, SSS, procedural patterns that the glTF PBR model cannot express), the options are: (a) bake the Combined/diffuse lighting into base color and export as KHR_materials_unlit, accepting no dynamic lighting; (b) bake only AO and lighting-independent albedo, then re-light in three.js with an HDRI (section 5); (c) skip realtime and use pre-rendered media (section 4). Which is better depends on whether the object must be re-lit or only rotated.
- Atlas strategy: for a multi-part model (e.g. a T-shirt mockup with print, labels and hardware) one atlas with one material cuts draw calls (Khronos mobile target is < 20 draw calls recommended, 500 absolute max; see section 3); `palette` helps only with flat-colored materials.

### Gaps
- The Blender manual Baking page itself could not be fetched; the Selected-to-Active / cage / margin facts rest on search-result summaries of that page.
- No primary source found for: Cycles Combined bake pass toggles (Direct/Indirect/Color) for lightmap baking, bake sample counts, denoising settings, recommended margin sizes in pixels, bake of world/environment lighting, or how to export a lightmap via glTF (core glTF has only an occlusion slot; I did not find a fetched source documenting three.js `lightMap` use with GLTFLoader).
- Blender bake add-ons (SimpleBake, Bake Wrangler, atlas tools such as TexTools) were not researched; no sourced comparison available.

## 3. Optimization: polygon/texture/file budgets, KTX2, WebP/AVIF, glTF Transform, gltfpack, Draco vs Meshopt, LOD, instancing, loading strategy, measuring

### Takeaway
Use glTF Transform (v4.5.1 on main) as the primary optimizer: `optimize` defaults to meshopt geometry compression, 2048 px textures, instancing, join, weld, simplify and (optionally) KTX2 with UASTC for normal/ORM and ETC1S for color. Published budgets cluster around 3 MB / 150k triangles / 2K textures / under 20 draw calls for a single-item mobile web view (Khronos 3DC) and 100k triangles / one 2048 texture set for Apple AR Quick Look; cap textures at 2048 and verify with `inspect`.

### Cited Findings

**Budgets**
- Khronos 3D Commerce Publishing Targets (repo `main` file): file size 3 MB for Single-Item Mobile AR/3D Web Catalogue and for Single-Item Desktop 3D Web View, 1 MB for Web-based Planning Tool, 500 KB Banner Ad; triangles max 150,000 (mobile AR/3D web catalogue), 250,000 (desktop 3D web), 40,000 (planning tool), 30,000 (banner); draw calls "<20 (500)" mobile, "<100 (800)" desktop, "<5 (50)" planning, "<5 (100)" banner (value in parentheses presumably the absolute maximum vs recommended); JPG bitmap resolution 2K mobile and desktop, 1K planning tool, 512 banner — [Khronos 3DC Publishing Targets](https://raw.githubusercontent.com/mlimper/3DC-Asset-Creation/main/asset-creation-guidelines/full-version/sec99_PublishingTargets/PublishingTargets.md)
- Conflicting figure for the same guideline family: the earlier Khronos blog announcement is summarised as "file size ideally less than 5 MB" and "triangle count 100,000 or less" with power-of-two textures (snippet-only; likely the v1.0 numbers, while Khronos announced Asset Creation Guidelines 2.0 at SIGGRAPH 2025) — [Khronos 3DC guidelines blog (snippet)](https://www.khronos.org/blog/3d-commerce-working-group-releases-real-time-asset-creation-guidelines-to-assist-artists-create-efficient-reliable-models-for-retail-and-e-commerce); [Khronos Guidelines 2.0 blog (title only)](https://www.khronos.org/blog/introducing-asset-creation-guidelines-2.0-siggraph-2025)
- Apple staff answer on AR Quick Look: recommended 100K polygons, one set of 2048x2048 textures, 10 seconds of animation, "meant to ensure that all of our supported devices (down to iPhone 7) can load and display the model well"; newer devices allow more detail; Quick Look uses RealityKit which "should" support texture downsampling — [Apple Developer Forums thread 693867](https://developer.apple.com/forums/thread/693867)
- Sketchfab (snippet-only, uncertain provenance): never uses a texture larger than 8192x8192; recommends minimizing texture count/size; targets around 500,000 faces or fewer; 50 MB upload limit mentioned — [Sketchfab help (snippet)](https://help.sketchfab.com/en/articles/16152043)

**glTF Transform `optimize` (primary: CLI source)**
- Pipeline order: dedup, instance (default on; min 5 instances), palette (default on; min 5), flatten, join, weld, simplify (default on), resample, prune (attributes, solid textures -> factors), sparse, then texture compression, then mesh compression last — [glTF Transform CLI source](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/cli/src/cli.ts)
- Option defaults: `--compress meshopt` (choices draco | meshopt | quantize | false), `--meshopt-level high` (or medium), `--texture-compress auto` (recompress in the original format; choices ktx2 | webp | avif | auto | false), `--texture-size 2048`; help text: "KTX2 optimizes VRAM usage and performance; AVIF and WebP optimize transmission size" — [glTF Transform CLI source](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/cli/src/cli.ts)
- `simplify` defaults: ratio 0.0 and error 0.0001 (fraction of mesh radius), lockBorder false; the algorithm quits before the target ratio if error exceeds the threshold; examples: ratio=0.5/error=0.001; for best results `weld` first; based on meshoptimizer — [simplify.ts](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/functions/src/simplify.ts); [glTF Transform CLI source](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/cli/src/cli.ts)
- `--texture-compress ktx2` inside `optimize`: normalTexture, occlusionTexture and metallicRoughnessTexture slots -> UASTC (level 4, RDO on, lambda 4); every other slot -> ETC1S (quality 255); both resized to `--texture-size` — [glTF Transform CLI source](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/cli/src/cli.ts)
- `uastc` options: level 0-4 (quality 43.45 / 46.49 / 47.47 (default 2) / 48.01 / 48.24 dB), RDO lambda "good range [.25, 10]; for normal maps try [.25, .75]", RDO dictionary size 256-65536 (default 32768), `--zstd`, mipmaps toggle and filter; `etc1s` options: `--quality` 1-255, `--compression` 0-5; help advice: use UASTC for normal maps and ETC1S for others, and consider increasing texture resolution to hide ETC1S artifacts while keeping files smaller — [glTF Transform CLI source](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/cli/src/cli.ts)
- `webp` / `avif` commands: `--quality` 1-100, `--effort` 0-100, `--lossless`, `--slots` and `--pattern` filters (webp also `--near-lossless`); `resize` uses Lanczos3 (or Lanczos2), never enlarges, supports `--power-of-two nearest|ceil|floor` — [glTF Transform CLI source](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/cli/src/cli.ts)
- `draco` defaults: edgebreaker, encodeSpeed 5, decodeSpeed 5, quantize position 14 / normal 10 / color 8 / texcoord 12 / generic 12; Draco compresses triangle geometry only (not animation or textures); `weld` is required — [draco.ts](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/functions/src/draco.ts); [glTF Transform CLI source](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/cli/src/cli.ts)
- `meshopt` compresses geometry (points, lines, triangles), morph targets and animation tracks; "decodes very quickly, and is best used in combination with a lossless compression method like brotli or gzip"; default level high — [glTF Transform CLI source](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/cli/src/cli.ts); [meshopt.ts](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/functions/src/meshopt.ts)
- `quantize`: 32-bit float attributes -> 16/8-bit ints, requires KHR_mesh_quantization; a value quantized to 12 bits still occupies 16 bits on disk, so lower bit depths help gzip more — [glTF Transform CLI source](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/cli/src/cli.ts)
- `instance`: creates EXT_mesh_gpu_instancing for meshes reused by more than one node (default min 5); instanced meshes cannot be animated and must share materials — [glTF Transform CLI source](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/cli/src/cli.ts); [instance.ts](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/functions/src/instance.ts)
- `sparse` uses sparse accessors when >= 1/3 of values are zero (helps morph targets/shape keys); `copy` interleaves attributes and removes Draco "to avoid a lossy decompress/compress round trip"; `partition` splits .bin data for lazy loading (only for .gltf, not .glb) — [glTF Transform CLI source](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/cli/src/cli.ts)
- `inspect` prints a table of scenes, meshes, materials, textures and animations "useful for understanding how much of a file's size is comprised of geometry vs. textures", required extensions, and whether the scene is geometry-heavy, texture-heavy or has too many draw calls; supports `--format csv|md` — [glTF Transform CLI source](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/cli/src/cli.ts)
- Current glTF Transform version on `main`: 4.5.1 — [glTF Transform core package.json](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/core/package.json)

**gltfpack (meshoptimizer)**
- Flags: `-cc` (compressed output, needs EXT_meshopt_compression), `-c`, `-tc` (KTX2 with BasisU, KHR_texture_basisu), `-si R` (simplify to ratio R, default 1.0), `-mi` (EXT_mesh_gpu_instancing), `-noq` (disable quantization), `-vp/-vt/-vn/-vc` (quantization bits for position/texcoord/normal/color), `-vpf` (float positions), `-kn/-km/-ke` (keep named nodes/materials/extras). "meshoptimizer codecs are designed to produce output that can be compressed further with general purpose compressors like gzip/deflate." Draco is not supported by gltfpack — [gltfpack README](https://raw.githubusercontent.com/zeux/meshoptimizer/master/gltf/README.md)

**KTX2 / Basis facts**
- ETC1S: smaller files, weaker on complex high-contrast textures; UASTC: higher quality, suited to packed textures with very different RGB channel values (normal, ORM). Recommended codec by texture: Base Color ETC1S (UASTC if prominent/high-variation), Normal UASTC, ORM UASTC, Emissive ETC1S unless prominent, Transmission/Clearcoat UASTC — [Khronos KTX Artist Guide](https://raw.githubusercontent.com/KhronosGroup/3D-Formats-Guidelines/main/KTXArtistGuide.md)
- Measured GPU-memory savings: StainedGlassLamp 13 MB file / 96 MB GPU -> 10 MB file / 21 MB GPU ("81% of the file size and just 22% of the GPU size"); Duck PNG 118 KB file / 1.5 MB GPU -> KTX 116 KB / 277 KB GPU (about 82% GPU savings) — [Khronos KTX Artist Guide](https://raw.githubusercontent.com/KhronosGroup/3D-Formats-Guidelines/main/KTXArtistGuide.md)
- KHR_texture_basisu requires dimensions that are multiples of 4; guide states power-of-two dimensions; mip chain uses truncating division with minimum 1 — [Khronos KTX Artist Guide](https://raw.githubusercontent.com/KhronosGroup/3D-Formats-Guidelines/main/KTXArtistGuide.md)
- `toktx` flags documented there: `--t2`, `--encode uastc|etc1s`, `--uastc_quality 0-4`, `--uastc_rdo_l`, `--uastc_rdo_d`, `--zcmp 0-22`, `--genmipmap`, `--assign_oetf linear`, `--assign_primaries none` — [Khronos KTX Artist Guide](https://raw.githubusercontent.com/KhronosGroup/3D-Formats-Guidelines/main/KTXArtistGuide.md)
- three.js: BasisTextureLoader was removed (use KTX2Loader); `KTX2Loader.detectSupportAsync()` deprecated in favour of `detectSupport()` after `await renderer.init()` (r180 -> r181) — [three.js Migration Guide](https://raw.githubusercontent.com/wiki/mrdoob/three.js/Migration-Guide.md)

**Runtime loading (model-viewer docs, primary)**
- `reveal` attribute: "auto" reveals as soon as loaded and rendered; "manual" keeps the poster until `dismissPoster()`; `loading`: auto/lazy/eager (auto equals lazy: loads when near viewport); custom poster via `slot="poster"`; default poster is white; Draco decoder and KTX2 transcoder load from a Google CDN by default (configurable via `dracoDecoderLocation`, `ktx2TranscoderLocation`); the Meshopt decoder "is not enabled by default" (set `meshoptDecoderLocation`) — [model-viewer docs.json](https://raw.githubusercontent.com/google/model-viewer/master/packages/modelviewer.dev/data/docs.json)
- GLTFLoader's documented plugin list includes NEEDLE_progressive (progressive mesh/texture streaming) — [three.js GLTFLoader.js](https://raw.githubusercontent.com/mrdoob/three.js/master/examples/jsm/loaders/GLTFLoader.js)
- three.js r185 -> r186: `SimplifyModifier` was reimplemented on meshoptimizer and `modify()` is now async — [three.js Migration Guide](https://raw.githubusercontent.com/wiki/mrdoob/three.js/Migration-Guide.md)

### Inferences
- Derived texture memory arithmetic (not from a source; simple math): an uncompressed RGBA8 2048x2048 texture is 16 MiB (about 21 MiB with mips); a 4x4-block GPU format at 8 bits/pixel (e.g. UASTC transcoded to BC7/ASTC 4x4) is 4 MiB (about 5.3 MiB with mips); this is why the Khronos examples show GPU savings of 78-82%. So a model with four 2048 PNG/JPEG textures costs ~85 MiB of GPU memory vs ~21 MiB as KTX2, which matters most on iOS Safari.
- Baseline command (inference, built from documented options): `gltf-transform optimize in.glb out.glb --compress meshopt --texture-compress ktx2 --texture-size 2048`; for art-directed hero assets consider `--simplify false` (default simplify is lossy and uses error 0.0001) and `--palette false` unless the model is made of flat-colored materials; add `--compress draco` only if the target runtime cannot load Meshopt (e.g. model-viewer without `meshoptDecoderLocation`).
- gltfpack equivalent (flags from README): `gltfpack -i in.glb -o out.glb -cc -tc` (+ `-si 0.5` for 50% simplification, `-mi` for instancing).
- Draco vs Meshopt decision rule: Meshopt = fast decode, compresses animation/morph targets, plays well with Brotli/gzip on the CDN; Draco = geometry-only, requires a WASM decoder download, `weld` first, and cannot be post-processed without decompression. Without a fetched benchmark, no size ratio is claimed here; default to Meshopt for animated/skinned assets and to either for static meshes.
- Delivery: serve .glb / .ktx2 / .wasm decoders with long-lived immutable cache headers and Brotli for the Meshopt-compressed GLB; KTX2 payloads are already Zstd-supercompressed (UASTC) or entropy-coded (ETC1S), so extra HTTP compression gives little. Self-hosting the Draco/KTX2/Meshopt decoders avoids Google-CDN requests (relevant for a DE/NL audience under GDPR; this legal point is the researcher's inference and not sourced).
- Loading strategy: render a poster still from Cycles (WebP/AVIF, aspect ratio matching the viewer) shown immediately; load the GLB only when the viewer enters the viewport (`loading="lazy"` / IntersectionObserver) or on user tap (`reveal="manual"`), keep the first-paint JS for 3D out of the critical path with a dynamic import in Next.js; target the Khronos 3 MB figure for the initial model, and defer extra variants/LODs.
- LOD: glTF has no core LOD mechanism; options are separate GLBs per tier (e.g. mobile ~50k triangles / 1K textures, desktop ~150k / 2K), runtime switching with three.js `LOD`, or the NEEDLE_progressive plugin. Instancing: mark repeated parts (buttons, bolts) as instances (`instance --min 5` default, Blender "GPU Instances" export).
- Measuring: use `gltf-transform inspect` offline (geometry vs texture weight, draw-call hints); in-browser the usual tools are `renderer.info` (calls/triangles/geometries/textures) and Spector.js / Chrome GPU tracing — these two are standard practice but I did not fetch a source for them.

### Gaps
- No fetched benchmark comparing Draco vs Meshopt compressed size/decode time, and no benchmark of ETC1S vs UASTC vs WebP/AVIF file sizes for the same texture set.
- Khronos mobile/desktop budgets disagree between the fetched repo file (3 MB / 150k / 250k) and the blog snippet (5 MB / 100k); Guidelines 2.0 page was blocked so the current official numbers are unconfirmed.
- Google Scene Viewer's own size/triangle limits could not be fetched (developers.google.com blocked).
- Sketchfab guideline numbers are snippet-only and of uncertain provenance.
- No source found for LOD best practice in glTF/three.js, or for `renderer.info`/Spector.js usage.
- glTF Transform prerequisites for KTX2 encoding (whether the `toktx` binary from KTX-Software must be installed) were not verified in this session.
- Vercel-specific limits (static file size, bandwidth, compression of .glb/.ktx2) were not researched.

## 4. Alternatives to realtime 3D: pre-rendered sequences, scroll-scrubbed video, alpha video, Lottie/APNG/sprites, Gaussian splats, photogrammetry, USDZ/Scene Viewer AR

### Takeaway
For a fixed-lighting product turntable, pre-rendered Cycles frames (canvas image sequence or all-intra video) retain full render quality at a predictable cost but get large quickly; transparent video needs two codecs (HEVC-with-alpha for Safari, VP9 WebM for others). Gaussian splats are now a ratified glTF extension (KHR_gaussian_splatting) but loaded in three.js only via a plugin; AR needs USDZ on iOS (model-viewer can generate it on the fly) and GLB on Android.

### Cited Findings

**Scroll-scrubbed video / image sequences (snippet-only; blogs)**
- Scrubbing `<video>.currentTime` is unreliable: seeking is asynchronous, keyframe distance causes stutter, mobile Safari restricts inline playback; seek-to-update lag of 50-150 ms depending on codec and keyframe distance is quoted; drawing an already decoded ImageBitmap to a canvas is synchronous and cheap — [Hon Tran: scroll-scrubbed video stutters fix (snippet)](https://www.hontran.dev/blog/scroll-scrubbed-video-stutters-fix)
- An all-intra encode gives frame-accurate scrubbing but gives up most compression; "a 1080p all-intra clip can blow past 100 MB" — [Hon Tran (snippet)](https://www.hontran.dev/blog/scroll-scrubbed-video-stutters-fix)
- Practical implementations use WebP frame sequences drawn on a canvas with GSAP ScrollTrigger (Next.js 15 example) — [DEV Community: scroll-scrubbed video portfolio (snippet)](https://dev.to/pratham7711/how-i-made-a-scroll-scrubbed-video-portfolio-fast-nextjs-15-gsap-canvas-1mj6)

**Alpha-channel video (snippet-only)**
- Safari supports HEVC with alpha but not alpha in WebM; Chrome (and Firefox/Edge) support VP9-with-alpha WebM but not HEVC alpha; the common solution is two `<source>` elements (HEVC for Safari, WebM for others); one example quotes 1.1 MB (VP9, Chrome/Firefox) vs 3.4 MB (HEVC, Safari) for the same clip, including a rotating-phone turntable demo — [Rotato: transparent videos for the web (snippet)](https://rotato.app/blog/transparent-videos-for-the-web); [Jake Archibald: video with transparency (title/snippet)](https://jakearchibald.com/2024/video-with-transparency/)

**Gaussian splats**
- KHR_gaussian_splatting README status line: "Complete, Ratified by the Khronos Group". Splats are stored as mesh primitives with `mode` POINTS; required properties `kernel` (only "ellipse" defined) and `colorSpace`; optional `sortingMethod` (default `cameraDistance`); required attributes include ROTATION, SCALE, OPACITY and spherical-harmonics degree-0 coefficients (degrees 1-3 optional); the glTF material is ignored; perspective projection is expected; contributors include Cesium, Niantic Spatial, Esri, Nvidia, Huawei, Autodesk — [KHR_gaussian_splatting README](https://raw.githubusercontent.com/KhronosGroup/glTF/main/extensions/2.0/Khronos/KHR_gaussian_splatting/README.md)
- Compression is a separate extension (KHR_gaussian_splatting_compression_spz); SPZ is an open format from Niantic Spatial claimed to give up to ~90% size reduction vs PLY (snippet-only); Khronos published a release candidate in February 2026 with ratification targeted for Q2 2026 (snippet-only; the README above now shows ratified) — [Digital Production, Feb 2026 (snippet)](https://digitalproduction.com/2026/02/04/gltf-learns-to-splat-without-losing-the-plot/); [Digital Production, Sep 2025 (snippet)](https://digitalproduction.com/2025/09/02/3d-gaussian-splats-officially-added-to-gltf-standard/)
- Viewer support: glTF Sample Viewer lists KHR_gaussian_splatting as implemented; three.js GLTFLoader supports it only through a separately registered plugin; early adopters named in coverage are CesiumJS, Esri ArcGIS, Scaniverse (snippet-only) — [glTF Sample Viewer README](https://raw.githubusercontent.com/KhronosGroup/glTF-Sample-Viewer/main/README.md); [three.js GLTFLoader.js](https://raw.githubusercontent.com/mrdoob/three.js/master/examples/jsm/loaders/GLTFLoader.js); [Radiancefields.com Khronos coverage (snippet)](https://radiancefields.com/platforms/the-khronos-group-2)

**AR: USDZ (iOS) and GLB (Android)**
- model-viewer `ar-modes` is a prioritized list of `webxr`, `scene-viewer` (Android Scene Viewer app) and `quick-look` (iOS Quick Look); "Including quick-look here without an ios-src (our default) will generate a USDZ on the fly"; on-the-fly generation reflects scene-graph API edits but "is not perfect, for instance animations are not yet supported, so ... supplying ios-src may give better results"; `ar-usdz-max-texture-size` caps texture resolution in the generated USDZ; the load-progress event reports reason `usdz-conversion` — [model-viewer docs.json](https://raw.githubusercontent.com/google/model-viewer/master/packages/modelviewer.dev/data/docs.json)
- Apple's USDZ recommendations: 100K polygons, one 2048x2048 texture set, 10 s of animation, aimed at devices down to iPhone 7 — [Apple Developer Forums thread 693867](https://developer.apple.com/forums/thread/693867)
- AR Quick Look supports custom action buttons via URL parameters on the USDZ link (referenced in model-viewer docs to Apple's Apple Pay/custom action documentation) — [model-viewer docs.json](https://raw.githubusercontent.com/google/model-viewer/master/packages/modelviewer.dev/data/docs.json)

### Inferences
- Pre-rendered sequence budget (inference, simple arithmetic): 72 frames (5-degree steps) at 1200x1200 in WebP at ~25-60 KB each is roughly 2-4 MB, which is in line with the Khronos 3 MB single-item target; add AVIF for modern browsers if file size matters more than encode effort. The quoted blog figure says a 1080p all-intra clip "can blow past 100 MB", so all-intra video is only viable for short or small-resolution clips. The 72-frame figures are the researcher's illustration, not sourced.
- Mixing Cycles quality and interactivity: (a) pre-rendered turntable as the poster/hero with the real 3D model lazy-loaded on interaction; (b) bake Cycles lighting into textures and export unlit (section 2) so rotation looks identical to the render; (c) pre-rendered background plate or video plus a lightweight transparent GLB overlay; (d) Cycles-rendered still variants (color options) swapped by Framer Motion without 3D at all, which fits the existing Printful-mockup-driven shop.
- Splats are best for captured real-world objects (photogrammetry alternative) rather than designed products; with a ratified glTF extension, a splat can travel in a GLB, but three.js needs a plugin and splat files are large without SPZ, so keep them out of the critical path.
- AR for a shop: provide a USDZ via model-viewer's on-the-fly path for static models; hand-export USDZ (Blender USD export or Reality Converter) only for animated models; Android Scene Viewer takes the GLB directly. Blender's USD/USDZ exporter specifics were not researched.

## 5. Image-based lighting and matching the Blender look in three.js (HDRI formats, PMREM, tone mapping, color space, exposure)

### Takeaway
three.js defaults to no tone mapping, exposure 1.0 and sRGB output; it offers AgX (value 6) and Khronos PBR Neutral (value 7), and Blender also has a Khronos PBR Neutral view transform, so "Neutral on both sides" is the most direct way to get a product-accurate match. Environment maps can be .hdr (HDRLoader), Ultra HDR JPEG (UltraHDRLoader), EXR, or KTX2 UASTC HDR, and three.js r187 changed PMREM generation so reflections shift slightly.

### Cited Findings
- three.js constants: NoToneMapping 0, Linear 1, Reinhard 2, Cineon 3, ACESFilmic 4, Custom 5, AgX 6, Neutral 7; NeutralToneMapping is "based on the Khronos 3D Commerce Group standard tone mapping" — [three.js constants.js](https://raw.githubusercontent.com/mrdoob/three.js/master/src/constants.js)
- WebGLRenderer defaults: `toneMapping = NoToneMapping`, `toneMappingExposure = 1.0`, output color space `SRGBColorSpace` — [three.js WebGLRenderer.js](https://raw.githubusercontent.com/mrdoob/three.js/master/src/renderers/WebGLRenderer.js)
- `THREE.ColorManagement.enabled` has been true by default since r152; inline tone mapping and output color space only apply when rendering to screen (r155), so with post-processing use `OutputPass` for tone mapping and color-space conversion — [three.js Migration Guide](https://raw.githubusercontent.com/wiki/mrdoob/three.js/Migration-Guide.md)
- model-viewer exposes `tone-mapping` values: neutral, aces, agx, reinhard, cineon, linear, none; `environment-image` accepts "neutral", "legacy" or a URL to a .hdr or .jpg file; with no environment set, default neutral lighting is used — [model-viewer docs.json](https://raw.githubusercontent.com/google/model-viewer/master/packages/modelviewer.dev/data/docs.json)
- Blender got a Khronos PBR Neutral view transform proposal/PR whose stated goal is a color-neutral view that can "exactly match common end-point renderers that have adopted this new standard, such as Three.js and Filament"; the operator is hue-preserving and only compresses highlights past a knee (snippet-only; Blender version in which it shipped not verified) — [Blender issue 118824](https://projects.blender.org/blender/blender/issues/118824); [Blender PR 118936](https://projects.blender.org/blender/blender/pulls/118936); [Blender devtalk thread](https://devtalk.blender.org/t/adding-pbr-neutral-tone-mapper/33602)
- A three.js forum thread questions whether three.js's AgX tone mapping matches Blender's AgX (title-level evidence only; content not read) — [three.js discourse: Is AGX tonemapping implemented correctly?](https://discourse.threejs.org/t/is-agx-tonemapping-implemented-correctly/60609)
- HDR loading: `RGBELoader` was renamed `HDRLoader` (r179 -> r180); `RGBMLoader` removed; `LogLuvLoader` removed; `HDRJPGLoader` removed in favour of `UltraHDRLoader` (r166 -> r167); `HDRLoader` default texture type HalfFloat; usage pattern: `envMap.mapping = THREE.EquirectangularReflectionMapping; scene.environment = envMap;` with a 1k .hdr example — [three.js Migration Guide](https://raw.githubusercontent.com/wiki/mrdoob/three.js/Migration-Guide.md); [three.js HDRLoader.js](https://raw.githubusercontent.com/mrdoob/three.js/master/examples/jsm/loaders/HDRLoader.js)
- UltraHDRLoader reads the Ultra HDR JPEG format (SDR image plus gain map, ISO 21496-1 and legacy XMP metadata); it requires JPEG headers, MPF container and gain-map metadata; existing HDR/EXR files can be converted with the MonoGrid gainmap-creator tool linked in the source — [three.js UltraHDRLoader.js](https://raw.githubusercontent.com/mrdoob/three.js/master/examples/jsm/loaders/UltraHDRLoader.js)
- KTX2Loader supports Basis UASTC HDR: if the device supports ASTC HDR it is used directly, otherwise transcoded to BC6H; `astcHDRSupported` is hard-coded false on the WebGPU path (pending gpuweb issue 3856) — [three.js KTX2Loader.js](https://raw.githubusercontent.com/mrdoob/three.js/master/examples/jsm/loaders/KTX2Loader.js)
- PMREMGenerator builds a prefiltered mipmapped radiance environment map in a CubeUV layout using GGX VNDF importance sampling — [three.js PMREMGenerator.js](https://raw.githubusercontent.com/mrdoob/three.js/master/src/extras/PMREMGenerator.js)
- r186 -> r187: "PMREMs are now based on cube render targets ... `CubeUVReflectionMapping` has been removed. The overall quality of PMREMs has been improved as well so materials will look slightly different"; `WebGLCubeRenderTarget` can no longer be used with WebGPURenderer (use `CubeRenderTarget`; r182 -> r183) — [three.js Migration Guide](https://raw.githubusercontent.com/wiki/mrdoob/three.js/Migration-Guide.md)
- Vendor claim (needle.tools, snippet-only): their "FastHDR" format (KTX2 supercompressed prefiltered environment maps in UASTC HDR) loads about 10x faster than EXR, up to 5x faster than Ultra HDR and uses around 95% less GPU memory — [Needle FastHDR article (snippet)](https://cloud.needle.tools/articles/fasthdr-environment-maps)
- Latest published three.js release on master: 0.186.1; the Migration Guide already has a 186 -> 187 section (dev is r187) — [three.js package.json](https://raw.githubusercontent.com/mrdoob/three.js/master/package.json); [three.js Migration Guide](https://raw.githubusercontent.com/wiki/mrdoob/three.js/Migration-Guide.md)

### Inferences
- Matching recipe (inference from the defaults above): in Blender set View Transform to Khronos PBR Neutral (or Standard) with Look None and Exposure 0; in three.js set `renderer.toneMapping = THREE.NeutralToneMapping` and keep `toneMappingExposure = 1`, `outputColorSpace = SRGBColorSpace` (default), base color textures flagged sRGB and ORM/normal textures linear (GLTFLoader sets this from glTF semantics). If the Blender scene uses AgX, use `THREE.AgXToneMapping` and expect small differences; the forum thread suggests the two AgX implementations are not guaranteed identical.
- Lighting parity: use the same HDRI in Blender World and as `scene.environment` (and `scene.background` if desired), then tune with `scene.environmentIntensity` rather than renderer exposure so tone mapping stays comparable; remove any extra Blender lights that cannot be reproduced (area lights/mesh emitters) or replace them with baked AO plus a few punctual lights (export Lighting Mode Standard, see section 1).
- HDRI delivery choices: 1k-2k equirect .hdr (RGBE, loaded as half float) is the simplest and best-supported; Ultra HDR JPEG is far smaller on the wire but needs UltraHDRLoader and decode at runtime; KTX2 UASTC HDR keeps VRAM low but requires BC6H/ASTC HDR and is the newest path. Pre-filtering at load (PMREM) has a one-time GPU cost; for a static environment, generate once and reuse the render target.
- After upgrading three.js to r187, re-check reflections: the PMREM implementation change alters their look slightly (documented), so verify side-by-side with Blender renders again.
- Blender "Standard" lights vs three.js light units, and Blender world-strength to `environmentIntensity` scaling, were not verified; treat them as calibration steps (render the same sphere/ColorChecker in both).

## 6. Validation and inspection tools

### Takeaway
Run the official glTF-Validator (via glTF Transform `validate` or the web tool) for spec correctness, glTF Transform `inspect` for size/draw-call analysis, and visually verify in at least two viewers (Khronos glTF Sample Viewer as the reference renderer, three.js-based gltf-viewer, and model-viewer as the actual delivery target).

### Cited Findings
- glTF-Validator: validates against glTF 2.0; outputs a JSON report with issues and asset stats; live drag-and-drop tool and npm package (`gltf-validator`) exist; checks JSON/GLB structure, accessor values (NaN, invalid quaternions, min/max, sparse accessors), animation data, image issues (warns on non-power-of-two dimensions), and extensions including EXT_texture_webp, KHR_animation_pointer (partial), KHR_lights_punctual, KHR_materials_anisotropy and others — [glTF-Validator README](https://raw.githubusercontent.com/KhronosGroup/glTF-Validator/main/README.md)
- glTF Transform `validate` runs the official validator and supports `--ignore <CODE>,...` to suppress specific issue codes; `inspect` reports model composition (see section 3) — [glTF Transform CLI source](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/cli/src/cli.ts)
- Khronos glTF Sample Viewer (reference renderer) lists implemented extensions including KHR_draco_mesh_compression, KHR_materials_anisotropy, _clearcoat, _diffuse_transmission, _dispersion, _emissive_strength, _ior, _iridescence, _sheen, _specular, _transmission, _unlit, _variants, _volume, KHR_animation_pointer, KHR_gaussian_splatting and KHR_interactivity (checkbox list) — [glTF Sample Viewer README](https://raw.githubusercontent.com/KhronosGroup/glTF-Sample-Viewer/main/README.md)
- Don McCurdy's three-gltf-viewer: drag-and-drop glTF 2.0 preview in WebGL with three.js, hosted at gltf-viewer.donmccurdy.com; known issue: limited drag-and-drop in Safari — [three-gltf-viewer README](https://raw.githubusercontent.com/donmccurdy/three-gltf-viewer/main/README.md)
- model-viewer (Google) is a web component for delivering models with built-in AR modes, poster/reveal handling and tone-mapping options (see sections 3-5) — [model-viewer docs.json](https://raw.githubusercontent.com/google/model-viewer/master/packages/modelviewer.dev/data/docs.json)
- A Khronos 3D Commerce Asset Validator exists as an npm package (`@mikefesta/3dc-validator`, third-party implementation of the 3DC guidelines checks) (snippet-only) — [3DC Validator README on jsDelivr](https://cdn.jsdelivr.net/npm/@mikefesta/3dc-validator@1.0.0/README.md)

### Inferences
- Suggested QA sequence: `gltf-transform validate out.glb` (zero errors; review warnings such as non-POT textures), `gltf-transform inspect out.glb` (check file split between geometry and textures, draw-call count, required extensions), open in Khronos Sample Viewer (reference lighting/materials), gltf-viewer.donmccurdy.com (three.js behaviour), then the production `<model-viewer>` or three.js page on a real iPhone and a mid-range Android to check memory and Safari-specific issues.
- If Blender output looks different in the Sample Viewer vs three.js, differences usually come from tone mapping/environment settings rather than the asset; compare under identical HDRI and tone mapper (Neutral) before debugging materials.

- Validator's complete list of supported extensions beyond the first lines of the README was not read.

## 7. End-to-end step-by-step pipeline and current runtime status (synthesis of sections 1-6)

### Takeaway
A defensible 2026 pipeline is: author and bake in Blender (PBR + baked AO/normal/ORM) -> export uncompressed GLB -> `gltf-transform optimize` (meshopt + KTX2, 2048 cap) -> validate/inspect -> deliver via a poster-first lazy loader (model-viewer or three.js with self-hosted decoders) -> optionally add USDZ for iOS AR; WebGPU is now shipped in all major browsers, but three.js still falls back to WebGL 2 and the classic WebGLRenderer remains the lowest-risk target for glTF display.

### Cited Findings
- WebGPU implementation status (gpuweb wiki): Chromium 113 on Mac/Windows/ChromeOS; Android (ARM/Qualcomm/Intel, Android 12+) from 121; Linux Intel Gen12+ from 144; Firefox 141 on Windows, 145 on macOS 26+ Apple Silicon and 147 on all macOS versions, Linux/Android still Nightly or behind a flag (Mozilla expects Linux in 2026); Safari 26 on macOS, iOS/iPadOS and visionOS enabled by default — [gpuweb Implementation Status](https://raw.githubusercontent.com/wiki/gpuweb/gpuweb/Implementation-Status.md)
- three.js and WebGPU: node materials (TSL) work only with WebGPURenderer since the legacy WebGLNodeBuilder was removed (r163 -> r164); WebGPURenderer is imported from `three/webgpu` (r170 -> r171 notes); the renderer must be initialised (`await renderer.init()`) before sync methods; `renderAsync`/`computeAsync` deprecated (r180 -> r181); WebGPURenderer premultiplied-alpha behaviour changed in r185 (set an opaque clear color/background if blending looks wrong); shadow bias may need lowering after r183 improvements — [three.js Migration Guide](https://raw.githubusercontent.com/wiki/mrdoob/three.js/Migration-Guide.md)
- Blog-level claim (snippet-only): WebGPURenderer is "production-ready since r171" with automatic WebGL 2 fallback, and migration is often a one-line renderer swap — [Utsubo WebGPU migration guide (snippet)](https://www.utsubo.com/blog/webgpu-threejs-migration-guide)
- Tool versions on main at time of research: three.js 0.186.1 (r187 in development), glTF Transform 4.5.1, Blender glTF add-on 5.3.36 (Blender 5.3 baseline) — [three.js package.json](https://raw.githubusercontent.com/mrdoob/three.js/master/package.json); [glTF Transform core package.json](https://raw.githubusercontent.com/donmccurdy/glTF-Transform/main/packages/core/package.json); [Blender-IO __init__.py](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/addons/io_scene_gltf2/__init__.py)

### Inferences
Recommended pipeline (each step combines the cited defaults above; numbers marked "suggested" are rules of thumb):

1. Model for the budget: target <= 150k triangles hero (<= 100k if AR Quick Look is needed; <= 50k for a mobile LOD), < 20 materials-draw-calls ideal (Khronos mobile "<20 (500)"), one material/atlas per object where possible; apply scale/transform, triangulate-safe topology, unwrap non-overlapping UVs.
2. Bake in Cycles: normal map (Selected to Active, Tangent), AO, base color (Color pass only), roughness/metallic; pack ORM (R=AO, G=roughness, B=metal) as 8-bit PNG; export size suggestion 2048 hero / 1024 secondary / 512 small parts; keep UVs on 4x4 pixel block boundaries as far as practical.
3. Replace complex Cycles node trees with a Principled BSDF fed by the baked Image Textures (and `glTF Material Output` Occlusion); keep to extensions three.js and model-viewer support (clearcoat, sheen, transmission/volume sparingly, emissive_strength, texture_transform); use unlit + baked color where the render look must be exact.
4. Export: .glb, +Y Up, Apply Modifiers (only without shape keys), Images = Automatic/PNG (lossless), Draco/Meshopt off (compress later), no cameras/lights unless needed.
5. Optimize: `gltf-transform optimize in.glb out.glb --compress meshopt --texture-compress ktx2 --texture-size 2048` (flip `--simplify false` for hero assets); alternatives: `gltfpack -i in.glb -o out.glb -cc -tc`; for WebP/AVIF instead of KTX2 (smaller download, higher VRAM): `--texture-compress webp` or `avif` with `--quality` tuned; normal map UASTC with RDO lambda 0.25-0.75; color ETC1S quality 255 default (lower e.g. 128 only after visual check).
6. Validate and measure: `gltf-transform validate`, `gltf-transform inspect`, Khronos Sample Viewer, gltf-viewer.donmccurdy.com; check target of <= 3 MB for the first model request.
7. Environment and look: ship a 1k-2k .hdr (or Ultra HDR / KTX2 HDR) environment plus a Cycles-rendered poster still; set Neutral (or AgX) tone mapping identically in Blender and three.js/model-viewer; verify under r187's PMREM change.
8. Deliver: self-host GLB, decoders (Draco/KTX2/Meshopt WASM) and HDRI with long cache lifetimes; Brotli the GLB when using Meshopt; poster first, load model on viewport entry or tap; in Next.js, dynamically import the 3D code client-side only and keep `.blend`/source bakes out of the deployed repo.
9. AR (optional): `<model-viewer ar ar-modes="webxr scene-viewer quick-look">`; on-the-fly USDZ for static models, hand-built USDZ for animated ones (<= 100k polygons, one 2048 texture set, <= 10 s animation).
10. Choose realtime vs pre-rendered per asset: interactive materials/colour variants/AR -> GLB; fixed-light hero rotation -> WebP sequence on canvas or short all-intra/alpha video; captured real objects -> splat (KHR_gaussian_splatting) only if the extra payload is acceptable.
